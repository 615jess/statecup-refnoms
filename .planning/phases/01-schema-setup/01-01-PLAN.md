**Read the v1.0 scripts first** (`scripts/setup-confirmation-columns.gs` and `scripts/verify-sheet-structure.gs`) to carry forward the working patterns — then write new v2.0 replacements.

**1. Create `scripts/setup-schema-v2.gs`**

Write a single-file Apps Script with a `setupSchemaV2()` main entry point that does these steps in order:

1. **Rebuild header row A-Z** — Write all 26 headers in a single `setValues` call to row 1, columns 1-26. Use the exact header array from the research (locked below). Column Z gets an empty string (it's the named range target cell). Write "Confirmation Deadline:" label to AA1 (column 27) if not already present.

2. **Clear data rows** — If `getLastRow() > 1`, clear `A2:Z{lastRow}` using `clearContent()`. Log how many rows were cleared.

3. **Clear old validation then apply v2.0 status validation** — First call `sheet.getRange('S:S').clearDataValidations()` to remove any v1.0 rules on the entire column. Then build a new `DataValidation` rule with `requireValueInList(['Not Sent', 'Sent', 'Confirmed'], true)` and `setAllowInvalid(false)`. Apply to `S2:S500`. This ensures exactly 3 values, dropdown visible, invalid values rejected (not just warned).

4. **Create ConfirmationDeadline named range** — Check `ss.getRangeByName('ConfirmationDeadline')` first. If it exists, log and skip. If not, call `ss.setNamedRange('ConfirmationDeadline', sheet.getRange('Z1'))`.

5. **Clear old conditional formatting then apply v2.0 rules** — Call `sheet.clearConditionalFormatRules()` first. Then build 3 rules (Not Sent = gray #e8eaed/#3c4043, Sent = yellow #fef9c3/#854d0e, Confirmed = green #dcfce7/#166534) applied to `S2:S500`. Apply atomically with `sheet.setConditionalFormatRules(rules)`.

**Locked header array (A-Z, 26 columns):**
```
Timestamp, DRA Name, DRA Email, District, Referee #,
First Name, Last Name, Referee Email,
Phone, Age, Max Age as AR, Max Age as Ref,
Availability, Gender, Hotel Weekend 1, Hotel Weekend 2,
DRA Notes,
Token, Status, SentAt, SubmittedAt,
RefWeekend1, RefWeekend2, LateFlag, RefNotes,
(blank for Z)
```

**Conventions:**
- ES5 syntax throughout (`var`, no arrow functions, no template literals, string concatenation)
- Private helper functions prefixed with underscore (e.g., `_rebuildHeaderRow`)
- Public standalone wrappers for each step (e.g., `rebuildHeaderRow()` calls `_rebuildHeaderRow(sheet)`)
- Named column constants at the top for any column referenced by index (COL_STATUS = 19, etc.)
- Comprehensive `Logger.log()` for every step
- Script header comment block similar to v1.0 style: what, how to run, idempotency notes, column reference
- Idempotency: safe to run multiple times. The full header rebuild is unconditional (overwrites). Named range checks for existence. Validation clears before applying. Conditional formatting clears before applying.

**2. Create `scripts/verify-schema-v2.gs`**

Write a verification script with `verifySchemaV2()` as the main entry point, structured like v1.0's `verifySheetStructure()` with PASS/FAIL logging.

Checks to implement:
1. **Header check** — Read row 1, columns 1-26. Compare each header against the expected v2.0 array. Log each mismatch by column letter.
2. **Column count check** — `getLastColumn()` should be >= 26 (may be 27 with AA1 label). Accept 26 or 27.
3. **Status validation check** — Read validation rule from S2. Verify `getCriteriaType() === VALUE_IN_LIST` and `getCriteriaValues()[0]` matches `['Not Sent', 'Sent', 'Confirmed']` exactly.
4. **Named range check** — `ss.getRangeByName('ConfirmationDeadline')` exists and `getA1Notation()` contains 'Z1'.
5. **Data rows cleared check** — `getLastRow()` should be 1 (header only). If > 1, log FAIL with row count.
6. **Conditional formatting check** — `sheet.getConditionalFormatRules()` should return exactly 3 rules. Verify each rule's text-equals value matches the 3 statuses.
7. **AA1 label check** — `sheet.getRange(1, 27).getValue()` should be 'Confirmation Deadline:'.

Output a summary: `X passed, Y failed` with PASS/FAIL prefix on each line.

Same ES5 conventions as setup script. Same header comment block style.

**3. Create `.planning/COLUMN-MAP.md`**

Write the authoritative column reference document. Include:
- Full A-Z table with: Column letter, 1-based index, 0-based index, Header name, Writer (who writes this column), Phase (which phase implements writes)
- Named ranges section documenting ConfirmationDeadline at Z1
- Column constants section showing the named vars for downstream code (COL_TOKEN = 18, etc.)
- Notes on v1.0 -> v2.0 changes (header renames, writer changes)
- Clear statement that this document is the single source of truth for all phases

The column map must be consistent with the setup script's header array. Any discrepancy is a bug.
