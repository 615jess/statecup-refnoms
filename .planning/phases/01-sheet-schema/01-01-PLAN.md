  <action>
Create a `scripts/` directory at the project root. Write two Google Apps Script files.

**File 1: `scripts/setup-confirmation-columns.gs`**

Create a single main function `setupConfirmationColumns()` that performs all setup steps in the correct order, plus individual helper functions that can also be run standalone. The script must be idempotent — safe to run more than once (check before creating named range, skip backfill for rows that already have a Status value).

Functions to include:

1. `setupConfirmationColumns()` — main orchestrator that calls the others in order:
   a. Verify sheet has exactly 17 columns (throw error if not, unless it already has 25 meaning setup was already run)
   b. Add headers R1:Y1 using `sheet.getRange(1, 18, 1, 8).setValues([['Token', 'Status', 'SentAt', 'ConfirmedAt', 'RefWeekend1', 'RefWeekend2', 'RefHotel', 'RefNotes']])`
   c. Backfill column S (index 19, 1-based) with "Not Sent" for all existing data rows (row 2 through lastRow). Only write to cells that are currently empty (idempotent).
   d. Apply dropdown data validation on S2:S500 using `SpreadsheetApp.newDataValidation().requireValueInList(['Not Sent', 'Pending', 'Confirmed', 'Declined'], true).setAllowInvalid(false).build()`
   e. Create named range 'ConfirmationDeadline' pointing to Z1 (check if it already exists first using `ss.getRangeByName('ConfirmationDeadline')`)
   f. Add a label "Confirmation Deadline:" in Y1 — wait, Y1 is the RefNotes header. Use a different approach: place the label in cell Z1's comment or use AA1 as label and Z1 as value. Actually, looking at the research, the recommendation is Z1 for the deadline value. Since Y is the last data column header, put a label in a cell comment on Z1 or just let the named range be self-documenting. Simplest: write "Confirmation Deadline" as text in Z1 as a placeholder label, and note in the script's Logger output that the assignor should replace this with an actual date. OR: better approach — leave Z1 empty for the actual deadline date value, and put the text label "Confirmation Deadline:" in AA1 so the assignor sees it next to the cell. The named range 'ConfirmationDeadline' points to Z1.
   g. Optional: Add conditional formatting to column S (gray for Not Sent, yellow for Pending, green for Confirmed, red for Declined). Use `sheet.getRange('S2:S500')` with `SpreadsheetApp.newConditionalFormatRule()` for each status value.

CRITICAL column index rules (1-based for getRange):
- Column R (Token) = 18
- Column S (Status) = 19
- Column T (SentAt) = 20
- Column U (ConfirmedAt) = 21
- Column V (RefWeekend1) = 22
- Column W (RefWeekend2) = 23
- Column X (RefHotel) = 24
- Column Y (RefNotes) = 25
- Column Z (ConfirmationDeadline) = 26

NEVER use `insertColumns`, `insertColumnBefore`, or `appendRow` for headers. Only use `getRange().setValues()` and `getRange().setValue()`.

Add a header comment block at the top of the file explaining:
- What this script does
- That it's a one-time setup script
- How to run it (paste into Apps Script editor, run setupConfirmationColumns)
- That it's idempotent (safe to re-run)

**File 2: `scripts/verify-sheet-structure.gs`**

Create verification functions that confirm the setup worked and the nomination form is unaffected.

Functions to include:

1. `verifySheetStructure()` — checks:
   - Total column count is 25 (A-Y)
   - Headers R1:Y1 match expected values exactly
   - Column S has data validation rule applied
   - Named range 'ConfirmationDeadline' exists and points to Z1
   - All existing data rows have "Not Sent" in column S
   - Spot-check: columns A, F, G, Q of existing rows have data (not shifted)
   - Log results with clear PASS/FAIL for each check

2. `verifyNominationIntegrity()` — checks the last data row:
   - Columns A-Q have data (not empty)
   - Columns R-Y are empty (appendRow didn't spill into new columns)
   - Column Q value is a string (DRA Notes, not a shifted value)
   - Log results with clear PASS/FAIL

   Include a note in the function's JSDoc that the user should submit a test nomination through the form BEFORE running this function, so there's a fresh row to check.

3. `runAllVerification()` — calls both functions and logs a summary.

Each function should use `Logger.log()` for output (user views in Apps Script editor via View > Logs or the Execution log).
