<task type="auto">
  <name>Task 2: Wire JavaScript — page load fetch, form population, submission, and state transitions</name>
  <files>referee-details.html</files>
  <action>
Add all JavaScript logic to referee-details.html (in the existing script block after the HTML structure).

**Page load flow:**
1. Parse token from URL: `const token = new URLSearchParams(window.location.search).get('token') || '';`
2. If no token: `showState('error')` with message "No token found in URL." and assignor email empty (will be populated from response if available).
3. If token present: `showState('loading')` then call `loadRefereeData(token)`.

**loadRefereeData(token) — async function:**
1. `const url = SCRIPT_URL + '?token=' + encodeURIComponent(token);`
2. `const res = await fetch(url);` — NO options needed (no mode, no headers). Simple fetch.
3. If `!res.ok`: throw error with HTTP status.
4. `const data = await res.json();`
5. If `!data.ok`: showState('error') with data.message and data.assignorEmail.
6. If `data.deadlineState === 'hard_closed'`: showState('closed') with data.assignorEmail.
7. Otherwise: call `populateForm(data)`, then if `data.deadlineState === 'late'` show the late banner (set display:'' and populate deadline date), then showState('form').
8. Wrap entire function body in try/catch — catch shows error state with generic message.

**populateForm(data) function:**
Store `data` in a module-level variable (e.g., `let refereeData = null;`) for use in submit and state checks.

1. Set personalized greeting: firstName, draName, tournament dates, assignor email.
2. Set weekend toggles if prior data exists:
   - If `data.refWeekend1`: activate the corresponding toggle button (Yes or No)
   - If `data.refWeekend2`: same
   - IMPORTANT: Set toggles FIRST, then call `updateHotelVisibility()`, THEN set hotel values. Pre-fill order matters (RESEARCH.md Pitfall 7).
3. Set hotel values if prior data exists: hotelWkd1, hotelWkd2.
4. Set other fields: age, gender (set select value), phone, refNotes.
5. Set submit button text: `data.submittedAt ? 'Update Details' : 'Submit Details'`
6. Store whether this is a return visit: `let isReturnVisit = !!data.submittedAt;`

**Toggle button behavior:**
Each weekend has two toggle buttons (Yes / No). Clicking one activates it and deactivates the other. Use event listeners on each button.

When a toggle is clicked:
- Remove active class from sibling
- Add appropriate active class (`active-yes` or `active-no`)
- Set a hidden input or data attribute with the value ('Yes' or 'No')
- Call `updateHotelVisibility()`

**updateHotelVisibility() function:**
- Check Weekend 1 toggle value. If 'Yes': show hotel-wkd1 section. If 'No' or unset: hide it AND clear hotel-wkd1 value (prevent stale data — RESEARCH.md Pitfall 5).
- Same for Weekend 2.

**Form submission:**
Listen for submit event on the form (or click on submit button).

1. Validate required fields: both weekend toggles must be selected, age must be filled, gender must be selected, phone must be filled. Show inline errors on missing fields (add `.err` class, same pattern as DRA form).
2. Both-weekends-no check: if both weekends = 'No', show confirm dialog. If canceled, return.
3. Disable submit button, show spinner: `btn.disabled = true; btn.innerHTML = '<span class="spin"></span>Submitting...';`
4. Build payload:
   ```javascript
   {
     action: 'submitDetails',
     token: token,
     phone: phone.value.trim(),
     age: age.value.trim(),
     refWeekend1: weekend1Value,  // 'Yes' or 'No'
     refWeekend2: weekend2Value,
     hotelWkd1: hotelWkd1Value,   // 'Yes', 'No', or '' (cleared when weekend=No)
     hotelWkd2: hotelWkd2Value,
     gender: gender.value,
     availability: weekend1Value + ' / ' + weekend2Value,  // Summary for column M
     refNotes: notes.value.trim()
   }
   ```
   Column M (Availability) gets a summary string like "Yes / No" derived from the weekend toggles.
5. POST with no Content-Type header (same CORS pattern as DRA form):
   `fetch(SCRIPT_URL, { method: 'POST', body: JSON.stringify(payload) })`
6. Parse response. If `!data.ok`:
   - If `data.error === 'hard_closed'`: showState('closed')
   - Otherwise: show inline error message, re-enable button
7. If `data.ok`: showState('success'), populate success summary with submitted values.
8. In finally block: re-enable button, restore button text.

**showState(name, data) function:**
```javascript
const STATES = ['loading', 'form', 'closed', 'error', 'success'];
function showState(name) {
  STATES.forEach(s => {
    document.getElementById('state-' + s).style.display = s === name ? '' : 'none';
  });
}
```

**Inline error display** (for POST failures without losing form state):
Show a red error div below the submit button. Hide it on next submission attempt.

**DOMContentLoaded listener:** Wrap the page load flow in `document.addEventListener('DOMContentLoaded', function() { ... })` or place script at end of body (already at end if matching DRA form pattern).

ANTI-PATTERNS TO AVOID:
- Do NOT add `mode: 'no-cors'` to fetch — response body would be unreadable
- Do NOT add `Content-Type: application/json` header to POST — triggers CORS preflight that GAS can't handle
- Do NOT use `sheet.appendRow` anywhere — this form UPDATES existing rows
- Do NOT set LateFlag from the client — that's server-side only (the lateFlag in the response is for display only)
