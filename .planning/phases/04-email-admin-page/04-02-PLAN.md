5. **Inline JavaScript:**

**Constants:**
```javascript
var SCRIPT_URL = 'PASTE_NEW_DEPLOYMENT_URL_HERE';
```
Leave as placeholder — the user must paste the new deployment URL after creating a new Apps Script deployment.

**State:**
- `var allNominees = [];` — full dataset from API
- `var sortState = { col: 'status', dir: 'asc' };` — current sort (default: Not Sent first)

**loadNominees() — async function, called on DOMContentLoaded:**
- Show loading state, hide error state
- `var res = await fetch(SCRIPT_URL + '?action=getAllNominees');` — simple GET, no Content-Type header (CORS-safe pattern proven in Phase 3)
- Parse JSON response
- If !data.ok, throw error
- Store `allNominees = data.nominees` and `tournamentProps = data.props`
- Call renderSummary(), renderTable()
- Hide loading state
- On error: hide loading, show error state with error message and retry button

**renderSummary(nominees) — updates #summary div:**
- Count nominees by status: Not Sent, Sent, Confirmed
- Render total count + three badge-styled count spans
- Example: "25 Total | 12 Not Sent | 8 Sent | 5 Confirmed"

**sortNominees(nominees, col, dir) — returns new sorted array:**
- Status sort uses custom order: Not Sent=0, Sent=1, Confirmed=2
- Name sort: concatenate firstName + lastName, case-insensitive
- All other columns: case-insensitive string comparison
- Return `nominees.slice().sort(comparator)`

**renderTable() — clears and rebuilds tbody:**
- Apply current sort to allNominees
- Apply current search filter
- For each nominee, create a table row (`<tr data-token="...">`) with:
  - Name: `nominee.lastName, nominee.firstName`
  - Email: `nominee.refEmail`
  - DRA: `nominee.draName`
  - Status: badge span with appropriate class (badge-not-sent / badge-sent / badge-confirmed)
  - Wkd 1: `nominee.refWeekend1 || '—'`
  - Wkd 2: `nominee.refWeekend2 || '—'`
  - Action: Email button (enabled only for Not Sent status)
    - Button has `onclick="handleEmailClick(this)"`
    - Button has `data-token` attribute with nominee's token
    - Button has `data-mailto-href` attribute with pre-computed mailto URL (from buildMailtoHref)
    - For Sent status: button disabled, text "Sent"
    - For Confirmed status: button disabled, text "Confirmed"
- If no nominees match filter, show "No nominees found" row spanning all columns

**buildMailtoHref(nominee, props) — returns mailto: URL string:**
- To: nominee.refEmail (encoded)
- Subject: "State Cup Referee Nomination — Action Required" (use em dash character)
- Body (raw, before encoding — keep under 1600 characters):
  ```
  Dear [firstName],

  You have been nominated to officiate at the Tennessee State Cup tournament by [draName].

  Tournament Dates:
    Weekend 1: [weekend1Dates]
    Weekend 2: [weekend2Dates]

  Please complete your referee details using the link below:
  [refFormUrl]?token=[token]

  Please respond by [deadlineDisplay].

  If you have questions, please contact:
  [assignorEmail]

  Thank you,
  Tennessee State Cup Assignor
  ```
- Put the form URL on its own line (New Outlook may not auto-hyperlink — maximize copy-paste usability)
- Use `encodeURIComponent()` separately on subject and body
- Return `'mailto:' + encodeURIComponent(nominee.refEmail) + '?subject=' + encodeURIComponent(subject) + '&body=' + encodeURIComponent(body)`
- If deadlineDisplay is empty, omit the "Please respond by" line

**handleEmailClick(btn) — async onclick handler:**
- Read token from `btn.dataset.token`
- Read href from `btn.dataset.mailtoHref`
- Disable the button immediately (prevent double-click)
- Fire markSent API call (await):
  ```javascript
  var res = await fetch(SCRIPT_URL, {
    method: 'POST',
    body: JSON.stringify({ action: 'markSent', token: token })
  });
  ```
  Do NOT set Content-Type header (avoids CORS preflight — proven pattern from Phase 2/3)
- Parse response JSON
- If data.ok: call updateRowStatus(token, 'Sent') to update badge and button in-place
- If error: log warning but do NOT block Outlook from opening — show a brief console warning
- Open Outlook: `window.location.href = href;`
- The await ensures the sheet is marked Sent before Outlook opens (fetch is fast, <1 second)

**updateRowStatus(token, newStatus) — in-place DOM update:**
- Find tr with `data-token` matching token
- Update badge class and text to new status
- Disable the email button, change text to "Sent"
- Update the allNominees array so re-sorting preserves the change
- Re-render summary counts (one status changed)

**Column header click handlers:**
- Each `<th>` has `data-sort-col` attribute (e.g., "name", "email", "dra", "status")
- Clicking toggles sort direction (asc/desc) and calls renderTable()
- Show sort direction indicator (up/down arrow character in the header)

**Search handler:**
- `#search` input has an `input` event listener
- On each keystroke, filter `allNominees` by checking if `(firstName + lastName + refEmail).toLowerCase()` includes the search query
- Call renderTable() with filtered results (or re-render with filter applied)

**Error handling:**
- All fetch calls wrapped in try/catch
- Network errors show a toast or inline message (not alert())
- Retry button on error state calls loadNominees() again

**IMPORTANT design notes:**
- The page does NOT have any authentication. The URL itself is the access control (not linked publicly).
- The SCRIPT_URL is a placeholder — the user pastes the new deployment URL after creating a new deployment with the Phase 4 code.
- Match the visual design of existing pages: same topbar gradient, same hero layout, same fonts, same color palette. The admin page should look like it belongs to the same application.
