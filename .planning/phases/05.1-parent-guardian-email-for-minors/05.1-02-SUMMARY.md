# Phase 5.1 Plan 02: Frontend — Parent/Guardian Email Field + Admin Column Summary

Conditional parent/guardian email field added to referee-details.html (appears when age < 18, validated, submitted, pre-filled) and a sortable, searchable Parent Email column added to admin.html nominee table.

## What Was Built

### referee-details.html

- **HTML:** `#parent-email-row` div (hidden by default) added inside the Contact Details card below the age/gender/phone g3 grid. Contains a separator, explanatory note, and email input `#inp-parent-email`.
- **JavaScript — Visibility:** `updateParentEmailVisibility()` function reads `#inp-age` value; shows the row and marks field required when age is non-empty and < 18; hides row and clears value/error state otherwise. Wired to `input` event on `#inp-age`.
- **JavaScript — Validation:** `validateForm()` extended with a parent email block (only runs when row is visible): checks non-empty, checks basic email format (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`). Adds/removes `.err` class accordingly.
- **JavaScript — Payload:** `parentEmail` key added to POST payload object. Value is the trimmed input when visible, empty string when hidden.
- **JavaScript — Pre-fill:** `data.parentEmail` is set on the input in `populateForm()`, followed immediately by `updateParentEmailVisibility()` (called after `data.age` is already set on `#inp-age` — ordering is correct).
- **JavaScript — Success summary:** `showSuccessState()` conditionally appends a Parent/Guardian Email line when `payload.parentEmail` is truthy.

### admin.html

- **HTML — thead:** `<th data-sort-col="parentEmail">Parent Email</th>` added after Wkd 2, before Action.
- **JavaScript — tbody:** parentEmail td added between Wkd 2 td and Action td; displays value or em-dash for adults.
- **JavaScript — Sort:** `parentEmail` case added to `sortNominees()` comparator (case-insensitive string compare).
- **JavaScript — Filter:** `n.parentEmail` appended to search haystack string.
- **JavaScript — No-results row:** `colSpan` updated from 7 to 8.
